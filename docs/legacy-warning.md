# Legacy Warning — тех. долг и костыли

Явный список мест, которые работают, но при этом **не идеальны**. Сюда должны
попадать все компромиссы. Цель — чтобы никто не «внезапно узнал» про костыль.

Каждая запись имеет приоритет:
- 🔥 **критичный** — ломает прод / data loss / security (если есть — чинить срочно)
- ⚠ **архитектурный** — не ломает сейчас, но будет больно рефакторить потом
- 🧟 **стилевой / низкоприоритетный** — раздражает, но терпимо

Привязка к задачам — в [tasks.md](./tasks.md) § Phase C (колонка LW).

Формат:
```
## LW-<id> <название>  <приоритет>
- Где: путь:строка
- Симптом: что реально происходит
- Почему так: причина компромисса
- Когда чинить: триггер для плана работ
- Как починить: план
```

## LW-001 MCP `search_documents` ищет по имени файла  ⚠
- **Где**: `src/mcp/server.py::search_documents`
- **Симптом**: инструмент с «правильным» именем делает substring-match по
  `path.name`, а не по содержимому документа. Пользователь, который видит
  `search_documents("vacation policy")` в списке MCP-инструментов, ждёт
  семантический поиск.
- **Почему так**: это — **контракт legacy MCP-клиентов**. Переименование или
  смена семантики сломает внешние интеграции. Advanced Pipeline живёт рядом
  через `rag.query.retrieve()`.
- **Когда чинить**: когда появится второй инструмент с не-legacy семантикой
  (например, `semantic_search_documents`) и мы задепрекейтим старый.
- **Как починить**: добавить новый MCP-инструмент `semantic_search_documents`,
  который проксирует `rag.query.retrieve()`. `search_documents` оставить как
  есть, добавить deprecation note в docstring.

## LW-002 Дублированная загрузка `SentenceTransformer`  ⚠
- **Где**: `src/rag/embed.py` и `src/rag/query.py` — оба модуля при импорте
  делают `SentenceTransformer(EMBEDDING_MODEL)`.
- **Симптом**: при запуске CLI модель грузится дважды (~200 MB RAM × 2), вывод
  «Loading weights 100%» дублируется.
- **Почему так**: исторически. `embed.py` использовался отдельно для индексации,
  `query.py` — отдельно для поиска. Общий синглтон не выделен.
- **Когда чинить**: если RAM-профиль контейнера станет проблемой или если
  появится второй embedding-backend (например, HF inference endpoint).
- **Как починить**: вынести `src/rag/embeddings.py::get_embedding_model()`
  с `functools.lru_cache(maxsize=1)`, переиспользовать из обоих мест.

## LW-003 `QueryExpander` отключает LLM для всего non-ASCII  🧟
- **Где**: `src/rag/query_expansion.py::expand` — условие `q.isascii()`.
- **Симптом**: для длинных кириллических запросов LLM-rewrite не работает
  вообще, даже когда он помог бы.
- **Почему так**: маленькие LLM (`qwen3:0.6b`) «переводили» русские запросы
  в кривой английский, ломая и BM25, и embeddings. Стало хуже, чем без expansion.
- **Когда чинить**: когда появится RU-специфичная модель или когда можно
  протестировать `qwen2.5:7b` по-умолчанию.
- **Как починить**: вместо жёсткого `isascii()` проверить, что LLM-ответ тоже
  на кириллице (rough-check через `re`). Если смешанный язык или перевод —
  откатить.

## LW-004 `HybridSearchEngine.search()` пересинхронизирует чанки через `is not`  🧟
- **Где**: `src/rag/query.py::retrieve`
  ```python
  if engine.chunks is not chunks:
      engine.chunks = chunks
      engine.bm25 = BM25Index(chunks)
  ```
- **Симптом**: если `chunks` — тот же объект, проверка срабатывает один раз.
  Но если где-то выше чанки **пересобрали в месте** (добавили элементы в тот
  же список), BM25 не пересчитается.
- **Почему так**: дешёвый способ обновлять BM25 после `_ensure_index_exists()`
  без явного invalidation API.
- **Когда чинить**: при добавлении rebuild-команды в runtime.
- **Как починить**: явный `reset_pipeline()` после любого `build_index()`;
  не опираться на identity-check.

## LW-005 `chunks.pkl` — pickle, не JSON / protobuf  🧟
- **Где**: `src/rag/build_index.py`, `src/rag/query.py`.
- **Симптом**: формат привязан к версии Python / классам. При попытке прочитать
  из другого языка (JS, Rust) — нужна повторная реализация pickle.
- **Почему так**: быстро и просто для Python-only проекта.
- **Когда чинить**: при подключении не-Python-клиента.
- **Как починить**: заменить на JSON-Lines `chunks.jsonl` (потеряем немного
  скорости, но получим переносимость) или Parquet через `pyarrow`.

## LW-006 Огромный `.gitignore` с конфликтующими правилами  🧟
- **Где**: `.gitignore`.
- **Симптом**: раньше блокировал `docs/*.md` и корневой `README.md`. Было найдено
  в процессе коммита (исправлено в CR-001).
- **Почему так**: файл сгенерирован шаблонным gitignore, поверх которого кто-то
  дописал `docs/*.md` для knowledge-base документов. Потом knowledge-base
  переехала в `src/docs/`, правило не удалили.
- **Когда чинить**: уже исправлено в части `docs/`. Оставить как есть.
- **Как починить**: при следующем рефакторе — перейти на минимальный gitignore
  (5-10 строк) + whitelist подход.

## LW-007 Дефолт `qwen3:0.6b` даёт плохие ответы на русском  🧟
- **Где**: `src/config.py::OLLAMA_MODEL`, `docker-compose.yml`.
- **Симптом**: маленькая модель на коротких русских запросах часто говорит
  «нет информации» даже когда контекст есть.
- **Почему так**: явное решение пользователя — маленькая модель ради скорости
  на dev-машине. `qwen2.5:7b` тестировался, качество лучше, но пользователь
  откатил.
- **Когда чинить**: в зависимости от конкретной задачи/корпуса пользователя.
- **Как починить**: сделать профили `dev-small` / `ru-medium` / `prod-large` в
  `config.py` и переключать через env.

## LW-008 Cross-encoder по умолчанию выключен  🧟
- **Где**: `src/config.py::RERANKER_ENABLED = False`.
- **Симптом**: pipeline возвращает top-K прямо из RRF без переранжирования.
  Качество на «зашумлённых» корпусах страдает.
- **Почему так**: модель `BAAI/bge-reranker-base` весит ~400 MB. Её лишний
  pull в CI / dev-среде раздражает. Флаг оставлен off-by-default, dev
  включает вручную.
- **Когда чинить**: после первого реального bake-off на пользовательском корпусе.
- **Как починить**: включить `RERANKER_ENABLED = True`, либо собрать отдельный
  docker-образ `local-rag-mcp-app:full` с уже скачанной моделью.

## LW-009 `build_prompt` — один системный промпт для всех ролей  ⚠
- **Где**: `src/rag/query.py::build_prompt`.
- **Симптом**: один и тот же промпт используется для security-запросов, HR-FAQ,
  tech-документации. Нельзя настроить «персоналию» ассистента.
- **Почему так**: начинали с простого MVP.
- **Когда чинить**: при первой жалобе на тон или при расширении доменов.
- **Как починить**: `PROMPT_PROFILES: dict[str, str]` в `config.py`, выбор
  профиля по namespace / префиксу документа.

## LW-010 Interactive CLI не сохраняет историю запросов  ⚠
- **Где**: `src/main.py`, `src/assistant.py`.
- **Симптом**: всё, что набрал пользователь, пропадает при выходе. Метрики
  качества собирать не на чем.
- **Почему так**: MVP. Пользователь явно спросил про это в сессии.
- **Когда чинить**: приоритет LR-01 в `current-sprint.md`.
- **Как починить**: append-JSONL в `src/logs/queries.jsonl` со всем контекстом
  запроса (query, expanded, top_chunks, answer, sources, ts).
