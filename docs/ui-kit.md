# UI Kit

У проекта нет графического UI — единственный интерфейс для пользователя это
**терминал (CLI)**. Этот документ фиксирует визуальные соглашения, чтобы при
расширении CLI (или добавлении web-UI в будущем) было с чем сверяться.

## Визуальные соглашения CLI

### Цвета / формат
- Markdown-рендер ответов — через `rich.Markdown` + `rich.Console`.
- Пользовательский ввод — обычный `input()`, без readline.
- Строка-разделитель между запросами — `─` × 60 (`"─" * 60`).

### Префиксы-иконки (эмодзи как семантический маркер)

| Иконка | Значение | Где видно |
|---|---|---|
| `❓` | Запрос пользователя | CLI prompt |
| `🤖` | Ответ ассистента | после pipeline |
| `📚` | Источники ответа | после ответа |
| `🔧` | MCP-инструмент сработал | `assistant.query` |
| `📝` | Query expansion | `rag.query.retrieve` |
| `🔎` | Hybrid search стадия | `rag.query.retrieve` |
| `♻️` | Reranker стадия | `rag.query.retrieve` |
| `📥` | Загрузка документов | `rag.build_index` |
| `✂️` | Chunking | `rag.build_index` |
| `🧠` | Embeddings | `rag.build_index` |
| `📦` | Создание FAISS индекса | `rag.build_index` |
| `💾` | Сохранение индекса | `rag.build_index` |
| `✅` | Успешная операция | `rag.build_index`, MCP init |
| `❌` | Ошибка | `rag.build_index`, `rag.query` |
| `⚠️` | Warning (нефатально) | `rag.query._ensure_index_exists` |
| `👋` | Прощание | `main.py` |

### Команды пользователя в CLI

| Ввод | Действие |
|---|---|
| любой текст | RAG-вопрос → pipeline → ответ |
| `exit` / `quit` / `q` | Выход |
| пустая строка | Пропуск (continue) |

Ctrl-C корректно обрабатывается: вызывается `assistant.close()`.

### Вывод стадий pipeline (debug-лог)

```
📝 query expanded: 'sqli' → 'sqli SQL Injection vulnerability'
🔎 hybrid(rrf) → 20 candidates
  [ 1] score=0.0328  source=docs/http-errors.md
  [ 2] score=0.0164  source=docs/security/sqli.md
  ...
♻️  rerank → top-5         (видно только при RERANKER_ENABLED=True)
  [ 1] rerank_score=0.8912  source=docs/security/sqli.md
```

Каждый этап выводит:
1. Строку-заголовок с иконкой и количеством.
2. Топ-10 кандидатов с порядковым номером (правоцентрированный `[ N]`), скором и источником.

## Принципы

1. **Каждый этап pipeline логирует сам себя.** Иначе отладить регрессию качества невозможно.
2. **Один эмодзи = одна семантика.** Не плодить иконки.
3. **Не ломать copy-paste из терминала:** никаких ANSI-escape, кроме того, что выдаёт `rich`.
4. **Ответ ассистента — в Markdown.** Таблицы, списки, код — всё рендерится.
5. **Источники — после ответа, не внутри.** Это облегчает визуальную фильтрацию.

## Расширение на web-UI (backlog)

Если появится web-UI:
- Использовать те же иконки как визуальные маркеры стадий.
- Разделитель `─` × 60 → горизонтальная линия.
- Markdown-рендер — через `marked` / `react-markdown`.
- Логи pipeline показывать в сворачиваемом блоке «под ответом» — пользователю обычно они не нужны, но разработчику критичны.
