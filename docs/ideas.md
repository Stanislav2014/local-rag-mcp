# Ideas

Копилка сырых идей, которые **пока не задачи**. Задача оформляется через
[change-request.md](./change-request.md) и попадает в [tasks.md](./tasks.md).
Отсюда идея уходит в корзину или становится задачей.

Формат записи:
```
## <краткое название>
Дата добавления: YYYY-MM-DD
Источник: <пользователь / расследование / статья / сессия с Claude>
```

---

## Гибридный reranker через LLM-as-a-judge
Дата: 2026-04-13
Источник: brainstorm

Вместо cross-encoder попросить LLM (`qwen3:0.6b`) отсортировать top-20 по
релевантности — в духе «listwise reranking». Дешево (маленькая модель), можно
включать как альтернативу `RERANKER_ENABLED`.

## SQLite-vector fallback
Дата: 2026-04-13
Источник: manbot (использует sqlite-vss)

Для окружений где faiss сложно поставить (Windows arm, альпайн) — fallback на
SQLite + ручное cosine (или sqlite-vss когда доступен). Добавить абстракцию
`VectorBackend` и переключатель в `config.py`.

## Query feedback loop
Дата: 2026-04-13
Источник: расширение D-02

После ответа спрашивать 👍/👎. Писать в `queries.jsonl`. Использовать для
обучения метрик и отладки reranker.

## Chunk-level citations в ответе
Дата: 2026-04-13
Источник: read of bge-reranker docs

В ответе ставить маркеры `[1]`, `[2]` привязанные к конкретным чанкам
(не только к документам). Пользователь сможет по клику увидеть откуда именно
пришёл фрагмент.

## Watchdog на `src/docs/`
Дата: 2026-04-13
Источник: dev experience

При изменении файлов в `src/docs/` автоматически триггерить `build-index`
(через `watchdog`). Сейчас приходится руками гонять команду.

## MCP-прокси для ollama как «tool»
Дата: 2026-04-14
Источник: brainstorm

Выставить ollama как MCP tool (`call_llm(prompt, model)`). Тогда ассистент
может делать цепочки «retrieve → reason → retrieve → answer» через один
унифицированный tool-протокол.
