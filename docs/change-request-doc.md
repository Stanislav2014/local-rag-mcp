# Change Request — Template

Это **шаблон**. Реальные данные текущей задачи живут в
[change-request.md](./change-request.md), который **заполняется при старте
задачи и очищается после merge**.

Перед стартом новой задачи: скопировать секцию ниже в `change-request.md`,
заполнить, оставить до merge.

---

## CR-<NNN> <Название задачи>
- **Дата:** YYYY-MM-DD
- **Автор:** <кто>
- **Задача:** <ID из tasks.md, ссылка на тикет, ветка>
- **Фаза:** A / B / C / D
- **Оценка:** <S / M / L или дни>

### Motivation (Why)
<1-3 абзаца: зачем делаем, какую проблему решаем, какой будет success criteria>

### Затронутые компоненты
- `путь/к/файлу.py` — что меняется, почему
- `путь/к/другому.py` — ...
- **Новые файлы:** `...`
- **Удаляемые файлы:** `...`

### Публичный API
- Сигнатуры / контракты, которые меняются
- Обратная совместимость: да / нет, если нет — migration notes
- **НЕ трогаем** (явное напоминание): MCP-инструменты, публичный API потребителей

### Риски
1. **<Название риска>** — что может сломаться, как мониторить, как откатить
2. ...

### Pending action items
_Concrete TODO (не uncertainty!)._ Формат:

- [ ] **A1** — <название>
  - State: <текущее состояние>
  - Options: <1-3 варианта реализации, если применимо>
  - Verify: <критерий успеха>
  - Owner: <кто>
  - Blocked by: <A2, A3 или —>

### Uncertainty
_Что неясно и нужно сначала разобраться._ Если много открытых вопросов — завести
записи в [discuss.md](./discuss.md).

- ...

### Тесты
- **Что добавляем:** новые юнит-тесты, интеграционные, e2e
- **Что обновляем:** существующие тесты (если меняется ожидаемое поведение)
- **Regression gates:** какие существующие тесты не должны ослабляться

### Документация
- Что обновить в `architecture.md`, `context-dump.md`, `legacy-warning.md`,
  `current-sprint.md`, `tasks.md` после merge.
